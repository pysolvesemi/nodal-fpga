# DFT and manufacturing-test track

[Roadmap index](../README.md) · [Progress rules](../progress.md) · [Functional verification](08-verification.md) · [Physical implementation](11-physical-implementation.md) · [Silicon/product qualification](12-commercial-qualification.md)

**Status:** Planned; all seven increments and their children remain open. Added 2026-09-16.

Global blocker: FND-08. DFT means design for testability. DFT-01–05 develop and verify pre-silicon test architecture, generators and deliverables. DFT-06/07 are post-silicon correlation and production-test qualification gates requiring externally produced measurements. Documentation, simulation, emulation and a generated test program cannot close an actual-silicon gate.

## Ownership and scope

Nodal-FPGA owns device-specific test intent, test-access RTL/wrappers, configuration/fabric diagnostic generation, resource-to-fault correspondence, independent validation, portable test packages and result correlation. Reuse qualified external scan-insertion, automatic test pattern generation (ATPG), fault-simulation, physical-design and tester tools through adapters; this track does not implement a general ATPG engine, ASIC physical engine, laboratory instrument or factory-management system.

Keep the existing Scala frontend/Rust backend and optional-CIRCT boundary. Intended modules, created only when implemented, are `core/rust/test-schema`, `compiler/rust/test-compiler`, `library/rtl/test`, `adapters/dft`, `adapters/tester`, and `verify/dft`, with headless commands under `apps/rust`. Reuse `adapters/fabulous`, `adapters/physical`, existing device/configuration/timing contracts and immutable artifact storage. Core must not import concrete device libraries, tool internals or proprietary data. This introduces no Nodal-HDL, nodal-eda or separate-repository implementation requirement. A genuine generic HDL/IR gap requires a separately reviewed owning-project change.

Labs, foundries, packaging/assembly and test partners perform physical measurements and manufacturing tests. This repository specifies needed capabilities, exports test artifacts, imports traceable results and records qualification evidence; it does not purchase equipment, book facilities, procure packages or operate production equipment. Restricted PDKs, vendor patterns and customer secrets stay outside redistributable artifacts. Roadmap approval does not authorize expenditure, tapeout or manufacturing.

## Stage and dependency contract

| Stage | Increments | Required outcome |
| --- | --- | --- |
| Pre-silicon architecture | DFT-01 | Fault/test-access contract and early bench/production-tester feasibility, before physical binding/hardening closure |
| Pre-silicon implementation | DFT-02, DFT-03, DFT-04 | Fixed-logic scan/access, storage testing and programmable-fabric tests; work may proceed in parallel after dependencies |
| Pre-silicon acceptance | DFT-05 | Exact implemented-netlist fault/test evidence and reproducible manufacturing-test package before PHY-04 |
| Post-silicon evidence | DFT-06 | Actual silicon correlates with the pre-silicon DFT package; required for PROD-02 closure |
| Production qualification | DFT-07 | Selected tester/process/package test flow is correlated and qualified; required for PROD-03 closure |

PHY-01 consumes DFT-01. PHY-02 consumes DFT-02/03 before its final hardened implementation closes. PHY-03 supplies post-layout/electrical results to DFT-05; it does **not** depend on DFT-05. PHY-04 then depends on DFT-05, transitively requiring DFT-01–04. DFT-06 depends on PHY-04, not on PROD-02; PROD-02 consumes DFT-06. DFT-07 consumes PROD-02 and feeds PROD-03. This direction avoids physical/DFT and silicon/product dependency cycles.

M0–M3 and ordinary generator/toolchain releases acquire no DFT, physical-silicon or production-equipment prerequisite. M4 requires pre-silicon DFT acceptance; M5 additionally requires real-silicon and production-test evidence. Preliminary experiments may precede a gate but cannot close it. Do not postpone pin access, tester timing, package/load-board/probe-card interfaces, at-speed capture feasibility or test-time budgeting until DFT-07: their plan and pre-silicon validation belong in DFT-01/05.

## Pre-silicon development and verification

- [ ] DFT-01 — Test architecture, fault model and reference baseline
  Depends on: FND-08.
  - [ ] DFT-01.a Specify fixed logic, configuration storage, LUT/FF/routing, clock/I/O and present hard-macro test partitions; define modeled faults, per-partition coverage denominators/targets, diagnostic resolution and area/power/test-time budgets. Separate functional resource coverage, modeled manufacturing-fault coverage and measured defect escape/yield; do not invent a universal coverage percentage.
  - [ ] DFT-01.b Define test-mode entry/exit, independent reset/clock access, safe output isolation and bootstrap diagnostics that do not assume a working programmable fabric, loader or result compactor. Distinguish configuration chains, internal scan access and IEEE 1149.1 boundary scan; a JTAG port alone provides none of the other guarantees. Define test/readback authorization and production/field restrictions for the selected lifecycle profile.
  - [ ] DFT-01.c Extend the existing independent assumption/correspondence ledger with a pinned FABulous capability inventory and reference-tool matrix. Record configuration transport, observable common resources, actual runtime-loading support, unavailable features and source revisions. Independently review fault locations, mappings and expected responses; a missing comparator capability never removes a Nodal requirement.
  - [ ] DFT-01.d Specify tester-neutral drive/sample events, clocks, directions, masks, levels, pin maps and artifact identities; identify external-clock, scan-shift versus at-speed capture, power/temperature and digital-capture capabilities. Review preliminary bench, wafer-probe and package-test feasibility with the intended test interface; document equipment access as an external dependency, not a purchasing milestone.
  - [ ] DFT-01.e Validate tiny independent fixtures for controllability/observability, unsafe configuration/output contention, broken loader/test access, wrong pin maps, missing test clocks and unauthorized modes. Record a technology-binding checklist for scan cells, storage ports and macro-test interfaces; default the initial digital profile to external clocking, with no PLL/DLL or RF-instrument prerequisite.
  - [ ] DFT-01.f Record the approved, revisioned test contract, measurable targets, reference scope, unresolved risks and final-head fixture evidence. No physical binding/hardening closure may bypass this contract; this does not claim implemented scan, ATPG or manufactured silicon.

- [ ] DFT-02 — Fixed-logic scan and boundary/test access
  Depends on: DFT-01, PHY-01, RTL-05.
  - [ ] DFT-02.a Integrate qualified external scan insertion for fixed configuration/boot/control logic and other selected partitions; bind actual library cells, chain partitions/order, clocks/resets, exclusions and test points. Record whether fabric FFs use scan, programmable tests or both from measured tradeoffs, not a blanket exclusion.
  - [ ] DFT-02.b Implement the declared test-access wrapper and its independent bootstrap/recovery path. For a full-chip profile claiming IEEE 1149.1, provide and independently check the TAP, boundary cells, supported instructions and matching BSDL/pin map; an embedded-fabric profile must provide an explicit tested host-access contract instead of claiming chip boundary scan.
  - [ ] DFT-02.c Generate initial stuck-at and applicable transition/at-speed ATPG patterns using a capability-qualified tool; verify chain stitching, shift/capture sequencing, scan-enable timing, reset overrides and clock-domain isolation. An unsupported model remains an explicit open obligation for a profile that requires it.
  - [ ] DFT-02.d Prove or independently check normal-mode equivalence of the DFT-inserted design while preserving legal programmability, including real reconfiguration between distinct designs. Test entry/exit safety and test-clock bypass without assuming an on-chip PLL or converting the manufactured fabric into a fixed diagnostic circuit.
  - [ ] DFT-02.e Run scan/TAP simulations and negative cases for broken/reordered chains, wrong cell polarity, missing clocks, wrong expected data and masked failures. Produce physical constraints and chain/cell correspondence for PHY-02; final post-route test-mode timing and regenerated patterns remain DFT-05 obligations.
  - [ ] DFT-02.f Record actual RTL/netlists, scan/access maps, pattern/tool hashes, initial fault reports, constraints, exclusions and final-head evidence for the selected implementation profile. Tool availability or successful scan insertion alone is not ATPG/fault-coverage qualification.

- [ ] DFT-03 — Configuration-storage and memory test
  Depends on: DFT-01, PHY-01, CFG-04.
  - [ ] DFT-03.a Bind storage-test requirements to the physical implementation: distributed flops/latches, addressable SRAM, and present BRAM/register-file macros have different ports and fault models. Require every implemented configuration state element to be writable and observably tested; choose protected readback, scan observation or another independently validated path.
  - [ ] DFT-03.b Implement storage-specific test controllers/access and read/write comparison. Use justified March/other memory algorithms for addressable memories with suitable ports, and appropriate shift/write/observe tests for distributed storage; never assume that calling a block configuration SRAM makes a generic MBIST interface exist.
  - [ ] DFT-03.c Verify the declared stuck-at, transition, address/decoder, coupling and retention obligations where applicable using independent fault models and expected results. State exact algorithm/model coverage; walking bits or one March variant must not be presented as proving every memory defect mechanism.
  - [ ] DFT-03.d Test access and error-reporting logic, first-failure address/bit or bounded diagnostic data, reset/abort and fault-free controls. Prevent illegal configuration patterns from causing electrical contention through isolation/quiescence, and restore a valid configuration before releasing outputs/user clocks.
  - [ ] DFT-03.e Define per-macro test, initialization, latency, read-during-write and repair/redundancy contracts where supported; test wrong maps, unsupported ports, masked faults and lifecycle restrictions. Absent BRAM/repair hardware is a declared profile capability, not fabricated implementation evidence; extending a profile reopens its relevant acceptance obligations.
  - [ ] DFT-03.f Record implemented storage-test RTL/wrappers, actual memory views, algorithms, fault-detection matrix, coverage limits and final-head evidence. Supply PHY-02 with physical test connections and DFT-05 with reproducible tests; unsupported required storage faults block qualification.

- [ ] DFT-04 — Programmable-fabric diagnostic generation
  Depends on: DFT-01, VER-03, CFG-04.
  - [ ] DFT-04.a Generate deterministic manufacturing-test configurations, stimulus and expected responses for LUT truth-table bits/mux paths, FF data/enable/reset modes, selectable routing and fixed links, boundary/corner tiles and present carry/DSP/BRAM resources. Keep resource IDs, configuration fields, RTL/netlist locations and test IDs explicitly correlated.
  - [ ] DFT-04.b Exercise both values and transitions on selected paths, mux isolation and nonselected paths, justified bridging/open models and relevant shared-control combinations. Track controllability/observability and classified exclusions without claiming all configurations or every physical bridge from edge coverage alone.
  - [ ] DFT-04.c Add regional clock reachability and separate launch/capture delay tests with declared clock relationships; counter operation alone is not setup/hold, skew or at-speed fault coverage. Partition activity to respect test-power/current constraints and prohibit unsafe arbitrary configurations or unintended oscillation.
  - [ ] DFT-04.d Build comparable small Nodal/FABulous fabrics using the pinned common subset and independent expected semantics. Exercise corresponding resources through each real loader and inject matched logical/configuration/routing faults where meaningful; compare behavior and detection matrices, not byte-identical bitstreams, routes or unrelated physical fault counts.
  - [ ] DFT-04.e Detect failures in the test generators, checkers and test resources themselves using independently authored fixtures, rotated test roles or fixed observation paths. Retain minimized counterexamples and uncertainty in diagnosis. Hierarchical forcing may implement labeled fault injection but cannot replace real loading or normal response observation.
  - [ ] DFT-04.f Record actual diagnostic bitstreams/vectors, independent expected responses, resource/fault mappings, comparator revisions and final-head detection/coverage results. An unavailable FABulous feature is documented and covered independently for Nodal; unsupported mandatory comparison runs do not silently pass.

- [ ] DFT-05 — Pre-silicon manufacturing-test acceptance
  Depends on: DFT-02, DFT-03, DFT-04, PHY-03.
  - [ ] DFT-05.a Regenerate/retarget and independently replay scan, storage and fabric tests on the exact post-synthesis and post-route implementation after final chain ordering/ECOs. Bind netlist/layout, device, package, cell/macro models, timing corners and all test artifacts to immutable hashes; revalidate normal-mode configuration preservation.
  - [ ] DFT-05.b Run qualified fault simulation/ATPG for each required partition/model, recording detected, undetected, untestable-with-evidence, aborted and excluded faults plus the counting/collapsing policy. Correlate semantic injection to actual structural fault sites where valid; RTL mutations are not a substitute for gate/library/memory fault coverage or analog defect characterization.
  - [ ] DFT-05.c Verify raw responses and any selected MISR/signature compaction with independent expected data, specified seed/polynomial/order/masks, reset handling and a stated aliasing analysis. Bound unknown/X handling and masking; fault-free tests, injected faults, corrupt signatures and corrupt checkers must produce the expected outcomes. A matching compact signature is not proof of zero faults or unique fault localization.
  - [ ] DFT-05.d Close scan-shift/capture and other test-mode STA, clock/reset-domain checks, appropriate timing-annotated simulation and test-power/IR/EM obligations using PHY-03 evidence. Model real at-speed launch/capture capability and disclose mixed-level/black-box/SDF limits; slow JTAG or FPGA emulation cannot qualify ASIC at-speed timing.
  - [ ] DFT-05.e Publish a reproducible tester-neutral package: scan patterns, storage sequences, fabric bitstreams, raw/compact expected responses, masks, pin/level/timing maps, bootstrap/recovery instructions and coverage reports. Validate adapters in simulation/dry-run against the selected test-interface contract, estimate load/shift/capture time and data volume, and review bench/ATE/load-board/probe-card feasibility before tapeout; actual tester correlation belongs to DFT-06/07.
  - [ ] DFT-05.f Independently approve the exact pre-silicon DFT dossier against DFT-01 targets and process/profile requirements. Missing tools, fault models, mandatory coverage or unreviewed exceptions block PHY-04; this gate certifies only its declared pre-silicon scope, not silicon yield, reliability, instrument accuracy or production readiness.

## Post-silicon and production evidence gates

These gates consume real external measurements. Test software, interface documentation and dry-run adapters are prepared above; they are not postponed until chips arrive. Successful scripts or simulated samples cannot close the following gates. Evidence can reference externally operated equipment without transferring lab/factory ownership to this repository.

- [ ] DFT-06 — Silicon DFT correlation gate
  Depends on: DFT-05, PHY-04.
  External blocker: authorized fabricated samples and accessible test facilities.
  - [ ] DFT-06.a Identify actual die/package revisions, sample/wafer/lot provenance when available, board/fixture revisions and instrument calibration/uncertainty; establish safe power/reset/external-clock/test access and independently validate the bootstrap path.
  - [ ] DFT-06.b Execute the frozen scan, configuration-storage and fabric diagnostic corpus on physical samples with the same test IDs, vectors and expected responses used pre-silicon. Exercise applicable boundary/host access, test abort/recovery and configuration restoration; retain raw measurements, not only pass summaries.
  - [ ] DFT-06.c Compare bench results with predictions over the justified voltage/temperature/frequency/sample matrix; distinguish tester/fixture errors, design/model mismatches and suspected manufacturing defects. Do not infer comprehensive process-corner coverage from a single die or claim an exact defect location from one signature.
  - [ ] DFT-06.d Investigate mismatches with reproducible failing sequences, alternative observations and reviewed diagnostic uncertainty. Record errata and retest any revised patterns/models against both simulations and silicon without overwriting original failures or silently changing expected responses.
  - [ ] DFT-06.e Import revisioned, integrity-checked result datasets and issue a correlation report for PROD-02/TMC-04. Changes to device timing/operating limits require characterization review and relevant regression replay, not automatic replacement from a single passing frequency sweep.
  - [ ] DFT-06.f Record independently reviewed actual-silicon DFT evidence, tested scope, failures/dispositions and remaining limitations. Keep this gate open until physical measurements support it; it does not replace broader PROD-02 characterization or authorize production.

- [ ] DFT-07 — Production-test qualification gate
  Depends on: DFT-06, PROD-02.
  External blocker: selected manufacturing/test partner, tester access and authorized production-qualification samples.
  - [ ] DFT-07.a Bind the pre-silicon portable test package to the chosen ATE/test-program, pin electronics, voltage/timing levels, load board/socket or wafer probe card and handler/temperature profile. Review intended wafer and packaged-final-test scope, or explicitly justified unavailable stages, with the manufacturing partner.
  - [ ] DFT-07.b Correlate tester results to the engineering bench using traceable samples and known reference outcomes; validate conversion, drive/sample timing, compare masks, scan/MBIST/fabric tests, continuity/leakage/current checks and approved operating-limit/speed-bin rules. Record discrepancies and guard-band rationale.
  - [ ] DFT-07.c Measure actual configuration/shift/capture overhead, total test time, data volume, test power and any multisite interactions; optimize patterns only with rechecked fault coverage and silicon correlation. Retain raw results and retest/binning rules sufficient to audit escapes and false rejects.
  - [ ] DFT-07.d Evaluate the justified sample/lot and operating-condition evidence for production acceptance. Keep modeled fault coverage, observed fallout/yield, defect escapes and reliability qualification separate; interface tests or limited samples cannot establish all four.
  - [ ] DFT-07.e Archive immutable production-test revisions, access-controlled partner evidence, wafer/package/sample traceability and change-control/requalification rules. Feed characterized datasets and errata to the device SDK and PROD-03; instrument ownership, continuous factory operation and logistics remain external.
  - [ ] DFT-07.f Record a reviewed production-test qualification decision for the exact device/process/package/tester combination. Missing actual correlation or mandatory acceptance evidence keeps PROD-03 open; subsequent changes to hardware, test program, masks, timing or models trigger impact review and appropriate requalification.

## Reference and acceptance rules

Reuse the [early FABulous baseline](../../verification-early-baseline.md) rather than introducing a second conflicting oracle. As a planning reference reviewed on 2026-09-16, the [FABulous fabric definition](https://fabulous.readthedocs.io/en/latest/user_guide/building_doc/fabric_definition.html) documents frame-based and `FlipFlopChain` configuration and states that configuration readback is unsupported. Its [simulation/emulation guide](https://fabulous.readthedocs.io/en/latest/user_guide/simulation/index.html) provides useful functional checking infrastructure. These are not evidence of an integrated scan/ATPG/MBIST/ATE manufacturing flow. DFT-01 must pin and audit actual source/tool revisions and record what is demonstrated, unavailable or incomparable; a moving documentation URL is not a qualified reference package.

[OpenROAD DFT documentation](https://openroad.readthedocs.io/en/latest/main/src/dft/README.html) describes scan-chain support and explicit limitations. [Siemens Tessent TestKompress](https://www.siemens.com/en-us/products/ic/tessent/test/testkompress/) provides a separate reference for ATPG/compression capability requirements. Evaluate qualified open or commercial adapters for the chosen cells/fault models; no vendor purchase or new ATPG implementation is mandated by these references. An open insertion flow is not automatically complete manufacturing-test signoff.

All completion follows [the nested-checklist policy](../progress.md). Profile-dependent applicability must be defined and independently checked; absent hardware is not permission to waive an existing required task. All seven parents and all 42 children remain unchecked in this documentation revision. This increment does not affect generated Verilog.
