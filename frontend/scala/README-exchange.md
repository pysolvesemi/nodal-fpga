# Minimal Scala exchange authoring witness

`FixtureWriter` generates actual UTF-8 exchange 0.1 bytes using the pinned Scala
3.3.8 / sbt 1.12.11 / Temurin 21.0.12.1+1 authoring profile. It is a small typed
fixture writer, not the production Scala DSL, an input JSON parser, a DeviceDB,
or an RTL/CAD implementation. The authoritative wire contract is
[`fnd-05-readiness.md`](../../docs/implementation/fnd-05-readiness.md).

## Reproduce and verify the authoring identity

From the repository root, after preparing the existing pinned tool cache:

```sh
source .cache/toolchains/env.sh
python3 frontend/scala/write-fixtures.py /tmp/nf-scala-example \
  --goldens verify/fixtures/exchange/goldens
```

Use a new output directory. The harness refuses overwrites and sbt command
metacharacters in paths. It checks the pinned JDK/Scala build, requests offline
sbt resolution from the prepared cache, checks formatting, compiles, runs the
writer checks, and runs the actual Scala writer. The normal sbt bootstrap/plugin
cache must already be prepared; this is not a cold-download or network-isolation
claim. Execution of the saved bytes in the separately reviewed prebuilt Rust
runtime is a different qualification step.

The writer implementation is one source file,
`src/main/scala/nodalfpga/exchange/FixtureWriter.scala`. Before invoking sbt the
harness computes its exact SHA-256, passes that digest to the writer, checks the
source is unchanged afterward, and verifies the emitted package's bound
`nodal-fpga/scala-fixture-writer` version `0.1` identity. Its named options record
`scala_compiler`, `scala_version`, `scalac_options`, `json_generator`, and
`json_generator_version`. The harness also verifies each emitted domain-separated
identity with Python's standard SHA-256 and verifies the raw architecture bytes
bound by the package. It publishes files only after these checks succeed.
This source identity is not publisher authentication.

Outputs:

- `architecture.json`, `package.json`, `design.json`: actual canonical full bytes
- `architecture.projection.json`, `package.projection.json`,
  `design.projection.json`: actual schema-directed canonical projections
- `identities.txt`: semantic/build IDs and actual output lengths/raw hashes
- `source-identity.txt`: writer source hash and authoring harness hash
- `authoring.log`: actual Scala check/generation and tool/classpath observations

Canonical JSON contains no BOM, incidental whitespace or final newline. No
filename is embedded in a manifest. The caller supplies the architecture's
exact file bytes to the Rust digest-addressed artifact resolver. The package
binds those bytes, not a presumed canonical replacement or a filesystem path.
The saved design binds this exact generated package build ID.

For direct integration with an already verifying harness:

```text
runMain nodalfpga.exchange.FixtureWriter <output-directory> <verified-source-sha256>
Test / runMain nodalfpga.exchange.WriterChecks [independent-full-goldens-directory]
```

The direct writer accepts a caller-verified source digest; use the Python harness
when the caller has not independently performed that verification. It is not a
source attestation service. The existing `BootstrapSmoke` main remains unchanged.

## Independent semantics and tests

The typed fixture implements the hand-stated primary semantics in
[`EXPECTED.md`](../../verify/fixtures/exchange/goldens/EXPECTED.md): one reusable
mux tile, three independent roots `t0/t1/t2`, two directed cross-root edges,
ordered `east/local/west` mux inputs, typed overlapping clock/configuration/power
domains and a two-bit selector with the exact set `{0,1,2}`. Keyed collections
are deliberately supplied in noncanonical order. One template is retained;
there is no flat graph or quantity-sized storage expansion.

Its semantic projection is byte-identical to the independent primary projection
and has ID
`0c5e51acf90f91981b7e3375e5ab58b05d20020aa51a594008f8d7a30e1c80a4`.
The full Scala architecture has its own honest provenance and optional annotation
payload. Its raw bytes differ from the hand corpus. The generated package binds
actual Scala authoring, whereas the independent hand package is explicitly
unbound/not-supplied. Their package IDs and corresponding design targets therefore
differ. No independent expected artifact is regenerated by this writer or harness.

`WriterChecks` uses fixed independent hash literals and optionally compares exact
independent projection files. It exercises:

- BigInt values at `2^53-1`, `2^53`, `2^53+1`, `2^63`, u64 maximum and overflow;
  malformed decoded unsigned spellings, u32 partitions, widths and range/span bounds
- strict surrogate rejection, exact UTF-8 name/key/provenance bounds,
  unsigned UTF-8 ordering including U+E000 versus U+10000, literal Unicode and
  slash, lowercase control escapes and minimal signed annotation integers
- all-array/all-object/mixed depth 64/65, string/collection/node/output caps,
  duplicate decoded keys and duplicate keyed-set identities
- canonical set permutations, ordered pin/mux changes against independent IDs,
  explicit schema-directed provenance/annotation projection, semantic renames,
  raw-artifact binding, source-identity changes and exact design target identity
- independent architecture and mapped-design projections, with the latter
  targeted explicitly to the independent hand package for that test only

The Scala writer validates its scalar constructions and keyed collection
identities. It does not copy the FND-04 semantic validator. Rust must check all
references, aliases, modes, selection consistency, design endpoint ownership and
artifact/package acceptance. Scala parser rejection is not claimed: there is no
Scala JSON input parser. Reader malformed-input coverage belongs to Rust and the
independent black-box corpus.

## Canonical writer and dependency boundary

The sole added dependency is exact Jackson core `2.21.5`, streaming generator
only. There is no databind, reflection, Jackson Scala module, parser, or floating
point conversion. The acquisition review noted later parser-only denial-of-service
fixes in upstream 2.21.7. This deliberately reviewed pin is restricted to the
unaffected generator path; parser and numeric-lookahead paths are unreachable
from this writer. Changing that usage requires dependency review, not implicit
permission to add JSON parsing.

Unsigned quantities are checked `BigInt` values and emitted only as decimal
strings. Typed records explicitly decide which provenance fields are omitted
from semantic output; there is no recursive field-name filter. Every emitted
object sorts decoded keys by unsigned UTF-8 bytes. Keyed collection comparators
follow their typed identities, while ordered pins, mux sources, scopes/paths and
annotation arrays retain order. Jackson emits JSON tokens; the writer does not
implement a tokenizer or concatenate JSON strings manually.

Canonical validation bounds depth at 64, each collection at 16,384, aggregate
values plus keys at 200,000, each decoded string/key at 65,536 UTF-8 bytes and
output at 8,388,608 bytes. A bounded output stream checks capacity before retaining
another generator chunk. These are proportional authoring safeguards, not an
exact process-memory or hostile-code sandbox guarantee. The tiny authored model,
projection tree and full tree exist transiently; no expanded connectivity graph,
bit array indexed by a declared quantity, or second authoritative ArchIR is built.

This increment does not affect generated Verilog.
